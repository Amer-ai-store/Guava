# تقرير التنفيذ والتحقق — TrustSoft

## النتيجة

أنجزت نسخة تطوير محلية داخل Guava؛ ليست لوحة إنتاج متصلة أو منشورة.
فحص البداية وجد README فقط، بلا تطبيق قائم أو ملفات مخطط أو تصدير.
لم يتغير أي مصدر TrustSoft أو نسخة تصدير أو سجل تحقيق.

## الأدلة المنفذة

- [نتائج 18 اختبارًا ناجحًا](evidence/unit-tests.txt): HTTP فعلي داخل الاختبارات،
  مصادقة، حجب مسارات كتابة/SQL حر، صلاحية cookie، رفض إدخال غير صالح،
  cache دون استعلام لكل طلب، تراجع الحالة عند انقطاع اصطناعي ثم استعادتها،
  استعلام محدود واقتباس معرفات ورفض ربط محقون وأذونات كاتب باستخدام موصل اصطناعي،
  TLS، مرشحات تحقيق دون تخمين مستخدم/جهاز، وفحص CSV متعدد الأسطر وفهرس غير مكتمل.
- [اختبار العملية الفعلية](evidence/live-smoke.txt): تشغيل خدمة Python مستقلة،
  جلب HTML، الدخول بمفتاح مؤقت غير مطبوع، قراءة snapshot، ورمز health=503 عند غياب SQL.
  أُوقفت عملية الاختبار وحدها. ليس اختبار اتصال SQL.
- [فحص SQL الفعلي](evidence/sql-probe.json): النتيجة blocked / sql_not_configured، خروج 1.
  لم ينجح استعلام SQL ولم تُعرض بيانات TrustSoft.
- [فحص مسار الوصول](evidence/access-probe.json):
  الاسم JAWAFFASVR غير قابل للحل من هذا runtime؛
  طلب HTTP إلى المنفذ 3456 أعاد 403، وقد يكون منع proxy لا رد الجسر.
  لا يوجد تصريح TCP أو VPN أو اعتماد SQL ظاهر في إعدادات البيئة، وأداة Desktop Commander
  غير متاحة ضمن أدوات هذه الجلسة. لا نعتبر غيابها هنا نفيًا لوجودها في جلسة أخرى.
- فحص بناء JavaScript: راجع evidence/frontend-check.json. ليس اختبار متصفح أو قبول بصري.

## المنجز البرمجي

- واجهة عربية متجاوبة بأقسام المبيعات والمشتريات والمحاسبة والشيكات والمخزون
  والمستخدمين والتقارير والمخطط والتحقيق.
- API محلي محمي بمفتاح وجلسة HttpOnly/SameSite/Secure؛ استعلامات ثابتة مقتصرة على القراءة،
  وحدود صفوف ومهل وتحقق من هوية الخادم والقاعدة، ورفض صلاحيات كتابة مكتشفة.
- اكتشاف أعمدة وأنواع وعلاقات معلنة عند توافر الاتصال. المخطط الحقيقي لم يُكتشف بعد.
- تحديث واجهة دوري وقراءة خلفية متسلسلة مع cache وتراجع محاولات وإظهار البيانات القديمة،
  وتنبيهات وسجل اتصال بالذاكرة. لا يوجد نظام تنبيه خارجي أو سجل تدقيق إنتاج دائم بعد.
- مرشحات تكرار دفعات وأحداث تعديل/فك ترحيل تعتمد ربطًا موثقًا. لا توجد نتائج تحقيق فعلية.
- أداة فحص CSV مستقلة للقراءة فقط، وأداة تشخيص PowerShell للخادم لا تغير الجدولة.
  PowerShell لم يُشغل هنا؛ الملفات الأصلية المذكورة لم تكن متاحة للفحص.
- تعليمات start_skill محفوظة بنجاح في مسودة البيئة. لم نغير install_script أو الشبكة
  أو روابط الأسرار والمتغيرات. الحفظ لا يعني تطبيقًا أو نشرًا.
  يلزم مراجعة وحفظ التغييرات في إعدادات البيئة ثم نشرها عندما يناسب ذلك؛
  هذا لا يزيل عائق الوصول إلى الإنتاج.

## معايير القبول

| المعيار | الحالة والدليل |
|---|---|
| استعلام SQL حقيقي للقراءة | محجوب: sql_not_configured، لا ادعاء نجاح |
| بيانات فعلية في اللوحة | غير منفذ؛ لا توجد بيانات تجريبية في مصدر التطبيق |
| تطابق عينات مع TrustSoft | غير منفذ؛ يلزم اتصال وتفسير معتمد لجداول الأعمال |
| التحديث التلقائي | منطق cache/الدورات واختبارات HTTP المحلية ناجح؛ تحديث بيانات إنتاج ومتصفح غير مثبت |
| استعادة اتصال بعد انقطاع آمن | ناجح بمصدر اصطناعي وHTTP محلي فقط؛ لم يُقطع أو يُختبر اتصال إنتاج |
| إصلاح الجسر والتصدير | غير منفذ عن بعد؛ التشخيص الآمن جاهز، سبب الفشل غير محدد |
| تحقيق سندات مفقودة | غير منفذ؛ العينة لا تثبت غياب سند، يلزم نطاق وتسلسل وإلغاءات كامل |
| نشر أونلاين آمن | غير منفذ؛ يلزم وصول وبنية TLS وهوية وصلاحيات ومراجعة أمنية |

## العوائق والخطوات التالية عند إتاحة الوصول

1. إتاحة أدوات المضيف الفعلية في الجلسة أو مسار شبكة خاص مصرح. لا يُستعاض عن ذلك
   بالتفويض النصي؛ لا يوجد عنوان قابل للوصول أو اعتماد نستطيع استنتاجه.
2. تشغيل inspect-server.ps1 على المضيف بحساب مصرح، ثم مراجعة محلية آمنة للسكربتين
   v2/v3 وسجل الفشل وإعداد الجسر وعقده، مع إبقاء النسخ والسجلات والعمليات كما هي أثناء التشخيص.
   لا يبدأ تصدير آخر أثناء العملية النشطة. معلومات PID 9276 و525 ملفًا و822 MB و1,024 جدولًا
   وتفاوت v2/v3 وردت من المستخدم، ولم تُثبت من هذه البيئة.
3. تهيئة مشغل SQL وهوية قراءة مُدققة وشهادة موثوقة، ثم probe_sql ومراجعة الهوية.
4. اعتماد الربط والأذونات والبيانات الحساسة وخطط الاستعلام على عروض مناسبة،
   ثم مطابقة عينات بالقيم والعملة والحالة والتاريخ مع TrustSoft.
5. اختبار التحديث على المصدر الفعلي واستعادة الاتصال بإيقاف موصل اللوحة فقط في بيئة اختبار،
   دون إيقاف SQL Server أو الشبكة العامة أو مهمة الإنتاج.
6. استكمال التقارير المالية بنطاقات كاملة وإجماليات موثقة، وتحقيق السندات بعد إثبات اكتمال الأدلة،
   ثم تقسية النشر واختبارات المتصفح والصلاحيات قبل الإتاحة العامة.

لا توجد نتيجة تثبت اكتمال المشروع أو جاهزيته الإنتاجية. التنفيذ المحلي والاختبارات أعلاه
موثقة، وما يتطلب الخادم محجوب بعائق وصول خارجي محدد.

## متابعة طلب الاتصال المباشر

أضيف scripts/probe-windows-sql.ps1 مع أربعة استعلامات SELECT مستقلة في scripts/sql.
يستخدم Windows Integrated Authentication وTLS موثوقًا للتحقق من أذونات القراءة
ثم هوية JAWAFFASVR/Jawafa_DB والمخطط والعلاقات دون Python أو جسر 3456.
[حزمة الفحص](deliverables/windows-sql-probe.zip) و[دليلها](WINDOWS-CONNECTION.md).
تم التحقق من سلامة أرشيف ZIP ووجود ملفاته الستة فقط؛ لم يُشغل PowerShell أو SQL على المضيف.
إعادة فحص الأدوات والسياسة أكدت عدم توافر Desktop Commander وVPN ومنح TCP؛
لم يُثبت اتصال جديد، ولم تُغيّر سياسات الشبكة أو بيانات اعتماد أو بيانات إنتاج.

## حزمة التنفيذ بواسطة مشغل السيرفر

[TrustSoft-Server-Check.zip](deliverables/TrustSoft-Server-Check.zip)
تحتوي START-HERE.txt بالعربية، ومشغل CMD وPowerShell، وفحص SQL، وفحص Windows
والتصدير، وأربعة استعلامات ثابتة وبيان SHA-256 داخلي.
تكتب نتائج مستقلة بأسماء فريدة داخل reports بجوار الحزمة، وتجمعها في ZIP.
لا تغير بيانات الإنتاج أو مهام الجدولة، ولا تشغل تصديرًا، ولا تنسخ محتويات سجلات أو CSV.
تحقق التغليف وهاش كل ملف ناجح: [دليل التحقق](evidence/windows-package.json).
لا يتوافر PowerShell في هذا runtime؛ لم يُختبر تنفيذ المشغّل أو الاتصال على Windows.
ينفذها المستخدم على JAWAFFASVR بهوية Windows مصرح لها بالقراءة ثم يرسل تقرير النتائج.
