# فحص مباشر لقاعدة Jawafa_DB

المسار يتجاوز الحاجة لجسر 3456 عبر اتصال SQL محلي معتمد، ولا يتجاوز سياسات الشبكة أو أذونات SQL.
يلزم تشغيل الأمر على JAWAFFASVR أو جهاز داخلي مصرح، بهوية Windows لها صلاحيات القراءة.
ليس حساب Administrator بديلًا لحساب قراءة؛ سيرفض الفحص صلاحيات كتابة/تنفيذ مكتشفة.

انسخ مجلد scripts مع المجلد الفرعي sql إلى مسار مستقل على المضيف،
ثم من Windows PowerShell 5.1 شغّل:

    powershell -NoProfile -File .\scripts\probe-windows-sql.ps1

إذا كان SQL على named instance معتمد، استخدم اسم المثيل الحقيقي بدل اختراعه:

    powershell -NoProfile -File .\scripts\probe-windows-sql.ps1 -Server 'JAWAFFASVR\INSTANCE_NAME'

لا يثبت هذا المثال اسم المثيل أو المنفذ الحاليين.
لا يتطلب Python أو pyodbc أو كلمة مرور في المحادثة.
يستخدم TLS مع تحقق الشهادة وWindows Integrated Authentication، وينفذ SELECT فقط.
فشل الشهادة يعالج بتثبيت شهادة SQL موثوقة وإعداد الثقة، لا بتعطيل التحقق.
لا يغير إعداد الخادم أو الخدمة أو الجدولة ولا يبدأ تصديرًا أو يوقف العملية 9276.

الناتج JSON على stdout فقط، ويمكن حفظه في تقرير مستقل جديد خارج مجلدات التصدير الأصلية.
يتضمن أسماء مخطط ومستخدم اتصال؛ احتفظ به محليًا محميًا، ولا تنشره علنًا.
النجاح يلزمه state=verified_read، وهوية الخادم والقاعدة الصحيحة، وخروج العملية 0.
حينها يصبح اكتشاف الأعمدة والعلاقات مثبتًا لهذه الهوية فقط.
لا يعد نجاحه إثبات مطابقة الأعمال أو اكتمال التحقيق أو اتصال لوحة Codex بالخادم.

السكربت مُعد ولم يُنفذ على Windows في جلسة Codex الحالية:
لا يوجد PowerShell محلي، ولا Desktop Commander متاح، ولا مسار TCP/VPN مصرح إلى الخادم.
لا يمكن للملف وحده نقل التنفيذ إلى جهاز Windows.
إذا كان حساب القراءة SQL-only ولا توجد هوية Windows مصرح لها، لا تحول إلى حساب أوسع؛
يلزم إعداد حساب الخدمة في المضيف بطريقة آمنة بواسطة مسؤول النظام.

بعد نجاح الفحص، استخدم المكتشف من المخطط لاعتماد ربط الأقسام ومطابقة العينات،
ثم شغّل الخدمة على مضيف داخلي بالهوية نفسها خلف HTTPS وصلاحيات مستخدمين مناسبة.
هذا يزيل الحاجة لفتح منفذ SQL للإنترنت أو تصدير كامل ومتكرر.
