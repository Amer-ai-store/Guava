# فحص الملفين وربط الوكيل

اللوحة المنشورة: https://trustsoft-control.zxzx-mohammad91.workers.dev/control

فُحص ملفا الاتصال المرفقان محليًا دون طباعة كلمة المرور أو نسخها إلى الموقع.
يتضمن ملف الإعدادات الخادم JAWAFFASVR والقاعدة Jawafa_DB وحساب SQL باسم sa.
هذه معلومات اتصال SQL وليست إذنًا تقنيًا لتنفيذ أوامر Windows عن بُعد.
لا يتضمن الملفان عنوان إنترنت للخادم أو قناة VPN أو اعتماد حساب Windows للمهمة.

الاختبار الحالي من السحابة: DNS المحلي لا يحل اسم JAWAFFASVR، والجسر القديم
http://JAWAFFASVR:3456 أعاد HTTP 403 من مسار proxy. لا يوجد VPN أو تصريح TCP مهيأ.
لا يثبت ذلك أن SQL متوقف أو أن كلمة المرور خاطئة؛ لم يصل الاختبار إلى مصادقة SQL.
أُعيد التحقق من الموقع ودخول الإدارة: HTTP 200، وonline=false وlast_seen=null.

## فحص SQL مرة واحدة على الشبكة الداخلية

1. فك TrustSoft-Windows-Connect.zip على JAWAFFASVR أو جهاز Windows داخلي مصرح له،
   في مجلد مستقل خارج C:\Export.
2. افتح Run-UploadedSqlCheck.cmd. اختر DBPrefernces.txt ثم ملف SQLPassword_Decrypted.
   لا تحتاج إلى لصق كلمة المرور أو تغيير أسماء ملفات التنزيل.
3. الفحص يفتح اتصال SQL مع تحقق TLS وينفذ استعلامَي SELECT ثابتين للهوية والأذونات.
   لا يصدر الجداول، ولا يغير SQL أو الحسابات أو المهام، ولا يثبت الوكيل تلقائيًا.
4. التقرير الجديد داخل reports/UploadedSQL-*.json. يمكن إرساله للتحقق؛ لا تُرسل ملف كلمة المرور.

نجاح sqlReadQuerySucceeded يثبت الاستعلام فقط. إذا ظهرت صلاحيات كتابة/إدارة يسجلها التقرير؛
هذا لا يجعل الحساب مقيدًا بالقراءة. طلب المستخدم صراحة دخول sa من الملفين؛ يدعم الوكيل
هذا المسار باستعلامات SELECT ثابتة فقط، ولا يغير صلاحيات SQL. لا يُنقل اعتماد SQL إلى
السحابة. يظل حساب قراءة محدود أفضل لتقليل الصلاحيات، دون اعتباره شرطًا يلغي تفويض sa الصريح.
لا تُعطّل TLS أو سياسة تنفيذ PowerShell لمعالجة الفشل؛ عالج الشهادة/الثقة والسياسة المعتمدة.
إذا منعت سياسة المؤسسة تشغيل السكربت، يلزم مسار التوقيع/التوزيع المعتمد لديها.

## تثبيت الاتصال الدائم على JAWAFFASVR مرة واحدة

1. ملف AGENT-KEY-PRIVATE.txt منفصل وسري، ليس داخل ZIP أو Git أو الموقع.
   انقله بأمان إلى مجلد الحزمة المفكوكة. لا تخلطه بمفتاح إدارة اللوحة أو كلمة مرور SQL.
2. افتح Install-LiveTrustSoftAgent.cmd على JAWAFFASVR. يطلب ارتفاع صلاحية التثبيت عبر UAC.
3. اختر ملف DBPrefernces.txt ثم ملف SQLPassword_Decrypted، كما طلب المستخدم لدخول sa.
   لا حاجة إلى إدخال كلمة المرور في سطر أوامر أو في لوحة الويب.
   ينشئ المثبت مهمة تحت حساب Windows المدمج LocalService بمستوى Limited؛ لا يستخدم SYSTEM
   ولا ينشئ مستخدمًا أو يوسع صلاحيات SQL. قد تكون رؤية خدمات/ملفات أخرى محدودة بهذه الهوية.
   تُذكر أخطاء الوصول في نتائج التشخيص بدل اعتبار البيانات غير المرئية غائبة.
4. بعد التثبيت افتح اللوحة وانتظر heartbeat واضغط فحص قاعدة البيانات.
   نجاح التثبيت وحده ليس دليل SQL؛ يلزم نتيجة verified_read للخادم والقاعدة الصحيحين.
   إن لم تسجل اللوحة أي نبضة تعرض «بانتظار أول اتصال من الخادم»؛ هذا لا يثبت عدم التثبيت.
   [نتيجة فحص القناة وإصلاح تعلّق الوكيل](CONNECTION-RECOVERY.md).

المثبت الجديد ينفذ فحص SQL حقيقيًا محدودًا قبل تشغيل المهمة ويحفظ النتيجة المنقحة في
ProgramData\TrustSoftAgent\data\install-sql-check.json. يميز نجاح الاستعلام من فشل الشهادة
أو المصادقة، ولا يعلن SQL ناجحًا عند فشل الفحص. تستمر مهمة الوكيل بإعادة المحاولة الآمنة.
هذا الفحص تحت هوية المثبت وباعتماد SQL الصريح؛ يلزم أيضًا إثبات النتيجة من مهمة LocalService
ونبضها في اللوحة. لم يُشغّل هذا المثبت على خادم الإنتاج في جلسة Codex.

المثبت يحافظ على أي تثبيت سابق، ولا يستبدله تلقائيًا. تبدأ مهمة الوكيل عند الإقلاع وتعيد
تشغيله عند توقفه، والاتصال صادر عبر HTTPS دون فتح منفذ SQL للإنترنت أو استخدام AnyDesk يوميًا.
لا يستطيع البرنامج تشغيل خادم مطفأ أو إصلاح انقطاع كهرباء/إنترنت مادي.

يحفظ المثبت اعتماد SQL في sql-credential.dpapi داخل ProgramData\TrustSoftAgent،
مشفرًا بواسطة DPAPI LocalMachine مع ACL محمي يمنح Administrators وSYSTEM تحكمًا كاملًا،
وLocalService قراءة فقط للكود والإعداد والاعتماد، وكتابة مجلد data فقط.
هذا تشفير مرتبط بجهاز الخادم مع حماية ACL؛ ليس عزلًا عن مسؤول الجهاز أو العمليات الأخرى
التي تعمل بالهوية نفسها. لا يحتوي config.json أو سطر أوامر المهمة على كلمة مرور SQL.
يفك كل فحص الاعتماد محليًا لفترة الاتصال، ولا يرسله إلى Cloudflare أو يحتفظ به في التقرير.
لا تُحذف الملفات الأصلية المرفقة ولا الصادرات ولا السجلات بعد التثبيت.

تبقى طريقة Windows Integrated Authentication السابقة متاحة عبر استدعاء المثبت الأساسي
دون ملفي SQL، بهوية Windows مصرح لها. وجود صلاحيات واسعة في هذه الطريقة يبقى مرفوضًا.
استثناء sa في الفحوص لا يُفعّل إلا بخيار AllowSaReadOnlyQueries الصريح ومستخدم SQL باسم sa؛
تسجل النتيجة accountReadOnlyEnforced=false وqueryPolicy=explicit_sa_fixed_selects_only.
لا توجد واجهة SQL حرة أو أمر كتابة أو تغيير صلاحيات أو استعادة نسخة في أزرار الوكيل.

## حدود التحقق

اختبارات محلل الإعدادات وسياسة sa وفحص نحو PowerShell على Linux لا تثبت تشغيل Windows أو SQL.
فرع اختبار DPAPI الحقيقي لا يعمل إلا على Windows؛ لم يُختبر هنا ويُوسم بأنه غير متحقق.
لم تنفذ هذه الجلسة استعلامًا ناجحًا على الإنتاج ولم تثبت الوكيل على الخادم؛ لا توجد قناة
تنفيذ عن بعد مهيأة في أدواتها. تبقى بيانات الأعمال والتقارير المالية ومطابقة العينات غير مثبتة.
