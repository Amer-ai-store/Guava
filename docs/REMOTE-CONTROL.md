# لوحة الاتصال والتعافي المخصصة

الواجهة الجديدة مستقلة على المسار /control من نفس مضيف المشروع، مهيأة للهاتف والكمبيوتر.
دخولها المباشر يستخدم مفتاح إدارة التشغيل، ولا يتطلب دخول المشاهدة المالية أولًا.
**نُشرت الواجهة وAPI فعليًا؛ لم يتصل JAWAFFASVR أو SQL بعد.**
المسار الحالي المجاني هو Cloudflare Workers + D1، وفق [دليل النشر](FREE-HOSTING.md).
إعداد Linux/SQLite أدناه بديل مستقل؛ للتثبيت على الخادم استخدم
[حزمة Windows المرتبطة بعنوان اللوحة الحقيقي](UPLOADED-SQL-CHECK.md).

## ما تفعله الأزرار

| الزر | التنفيذ داخل الخادم | الدليل المطلوب |
|---|---|---|
| فحص اتصال الخادم | خدمات ومستمع 3456 وعمليات ومهام وتصدير؛ قراءة فقط | نتيجة JSON ووقت heartbeat |
| فحص قاعدة البيانات | اتصال SQL جديد بهوية Windows للقارئ، مع TLS وتحقيق الأذونات والهوية والمخطط | state=verified_read واسم الخادم والقاعدة الصحيحان |
| إعادة محاولة الاتصال | إنشاء اتصال SQL جديد عبر الوكيل؛ لا يعيد تشغيل SQL أو جهاز Windows | نتيجة جديدة، وليس مجرد قبول الطلب |
| فحص ومراقبة التصدير | مقارنة جرد CSV بين عينتين، وحالة العمليات والمهام | count/bytes وأوقات العينة، دون استنتاج اكتمال |
| فحص النسخ الاحتياطية | جرد محدود من مسار النسخ المعتمد على الوكيل | ملفات وأحجام وأوقات؛ قابلية الاستعادة غير مثبتة |

تظهر النسخ المرفوعة إلى مضيف اللوحة عند ضبط TRUSTSOFT_BACKUP_DIR إلى مسار ملفات مركّب
للقراءة فقط. لم نكتشف مسار رفع أو حساب تخزين حاليًا. لا يوجد رفع تلقائي جديد أو تنزيل شامل
ولا تحميل تلقائي لنسخة قديمة على أنها بيانات حية.

## الاتصال دون AnyDesk

بعد تثبيت الوكيل **مرة واحدة**، يسحب طلبات محددة عبر HTTPS صادر.
لا توجد منافذ إدارة واردة أو PowerShell حر في API، ولا حاجة لبقاء جهازك الشخصي يعمل.
Task Scheduler يبدأ الوكيل عند إقلاع Windows، ويفحص تشغيل مهمته كل دقيقة مع IgnoreNew.
الوكيل يمسك قفل ملف محليًا لمنع نسختين؛ يعيد المحاولة مع تأخير وعشوائية يصل إلى نحو 303 ثوانٍ.
فحص SQL التلقائي كل 60 ثانية تقريبًا، وجرد الخادم والنسخ كل 300 ثانية عند توفر الوكيل.
الأوامر متسلسلة؛ كل فحص فرعي له مهلة 80 ثانية، ويُنهى عند تجاوزها الفحص الذي أنشأه الوكيل فقط.
لا تُنهى عملية تصدير أو SQL Server أو أداة مستخدم.

كل طلب له مدة صلاحية 120 ثانية وعقدة lease فريدة؛ لا يُنفذ طلب قديم عند عودة الاتصال.
نتيجة لم تُسلّم تحفظ في outbox محلي وتُرسل قبل أي طلب جديد.
إذا انقطع الوكيل وسط الفحص، تسجل نتيجة غير محسومة بدل الادعاء بالنجاح أو إعادة إجراء مجهول.
تُحفظ الأدلة المحلية في data/history دون تنظيف تلقائي.
طلبات الإدارة والنتائج وسجلها محفوظة في SQLite، دون تخزين أسرار في سجل الأحداث.
النتائج محدودة بـ8 MiB؛ تجاوز الحد يمنع إرسال تقرير ضخم بلا حدود.
حالة online تعني heartbeat منذ 90 ثانية أو أقل، وليس نجاح SQL أو اكتمال نسخة.

## البدائل وحدودها

| العطل | البديل المنفذ | ما لا يزال يحتاج بنية خارج الكود |
|---|---|---|
| توقف عملية الوكيل | إعادة تشغيل مهمته بواسطة Task Scheduler | إثبات ذلك عمليًا على Windows |
| انقطاع الشبكة المؤقت | retries وتأخير، وoutbox يحفظ النتيجة | عودة مسار الإنترنت الفعلي |
| تعطل عنوان HTTPS الأول | عنوان ثانٍ معتمد اختياري؛ TLS وبصمة هوية broker ثابتة | DNS وشهادة ومسار ثانٍ حقيقي |
| تعطل عملية اللوحة | قالب systemd مع restart وحفظ SQLite | مضيف دائم منشور ومختبر |
| رفض SQL أو الشهادة أو حساب كتابة | نتيجة خطأ محددة وإعادة فحص آمنة | إصلاح هوية القارئ والثقة والإعداد الصحيح |
| غياب المصدر الحي | عرض حالته القديمة صراحةً وجرد النسخ مستقلًا | ربط نسخة مكتملة ومطابقة قبل تحليل مالي عليها |
| انطفاء الخادم/الراوتر | بيان عدم الاتصال وانتظار عودة الجهاز | UPS أو قناة إدارة عتادية مستقلة/اتصال احتياطي |

العنوانان يجب أن يصلا إلى **نفس مخزن التحكم** ونفس broker_id.
لا تستخدم عنواني لوحتين مستقلتين بقاعدتي SQLite منفصلتين.
يمكن تشغيل brokers على مضيف واحد مع SQLite محلي مشترك وقفل معاملات؛
توفر عالي بين مضيفين يحتاج قاعدة تحكم مشتركة مدعومة وتصميم HA مختلف،
ولا يُفترض أن نسخ ملف SQLite بين مضيفين يحقق ذلك.
الوكيل يرفض عنوانًا ثانويًا بهوية broker مختلفة قبل إرسال نتيجة معلقة له.
الاسترجاع الشامل بعد فقدان الكهرباء/الإنترنت لا يمكن ضمانه بزر برمجي.

## إعداد مضيف اللوحة مرة واحدة

1. وفّر مضيف Linux دائمًا وعنوان HTTPS فعليًا وشهادة **موقع** موثوقة.
   لا توجد في هذه الجلسة أداة استضافة أو DNS أو نشر موقع؛ لا يوجد عنوان منشور يمكن اختراعه.
2. ضع المشروع في /opt/trustsoft، مع Python 3.12+ وحساب خدمة trustsoft.
3. من المشروع، بحساب مسؤول النشر:
       python3 -m scripts.prepare_control --directory /etc/trustsoft
   ينشئ dashboard.env وadmin-token.txt وagent-token.txt بأذونات 0600، ولا يطبع القيم.
   يعيد استخدام متغيرات المفاتيح الثلاثة إن كانت محقونة وصالحة، ويرفض استبدال ملفات موجودة.
   احتفظ بالمفاتيح في مخزن أسرار مضيفك، لا في المحادثة أو Git أو حزمة التحميل.
4. قالب deploy/trustsoft.service يستخدم source=agent وSQLite دائمًا داخل /var/lib/trustsoft.
   قالب deploy/nginx.example.conf يحتاج اسم DNS وشهادة الموقع الفعليين.
   القالبان لم يُفعّلا أو يُختبرا كنشر إنتاجي في هذه الجلسة.
5. ضع الملفات في مواقع الخدمة المناسبة، واختبر إعداد reverse proxy قبل تفعيله.
   لا تعرّض خادم Python مباشرة للإنترنت. استخدم جدارًا ناريًا وSSO/MFA عند النشر العام.
   المفاتيح الحالية تميز القارئ والمدير والوكيل، وليست حسابات شخصية متعددة.
6. افتح المسار /control على مضيفك وادخل بمفتاح admin-token.txt بطريقة آمنة.

متغيرات التشغيل:
- TRUSTSOFT_API_TOKEN: مشاهدة؛ لا ينفذ طلبات إدارة.
- TRUSTSOFT_ADMIN_TOKEN: إدارة منفصلة؛ لا تُقبل مساواته بمفتاح القارئ أو الوكيل.
- TRUSTSOFT_AGENT_TOKEN: اعتماد وكيل صادر؛ لا يُرسل إلى JavaScript.
- TRUSTSOFT_SOURCE=agent: قراءة مخطط موثق من نتائج الوكيل بدل محاولة SQL من السحابة.
- TRUSTSOFT_CONTROL_DB: مسار SQLite دائم خاص، وليس داخل دليل ويب.
- TRUSTSOFT_BACKUP_DIR: اختياري لجرد النسخ الموجودة على مضيف اللوحة.
- TRUSTSOFT_SECURE_COOKIE=1: مطلوب وراء HTTPS؛ القيمة 0 للتطوير على loopback فقط.

مصدر agent يعرض الهوية والمخطط والعلاقات فقط حاليًا.
ربط صفوف الأعمال والأرصدة والتقارير المالية عبر الوكيل **لم يُنفذ**؛ لن يعرض عينات مختلقة.

## إعداد JAWAFFASVR مرة واحدة

فك حزمة الوكيل على الخادم خارج C:\Export.
من Windows PowerShell 5.1 مرتفع الصلاحية، للتثبيت فقط:

    .\agent\Install-TrustSoftAgent.ps1 -DashboardUrl 'https://YOUR-REAL-DASHBOARD-HOST'

النص YOUR-REAL-DASHBOARD-HOST بديل يجب تغييره؛ ليس رابطًا منشورًا.
للمسار الثاني أضف -SecondaryDashboardUrl بعنوان HTTPS معتمد على نفس broker.
يمكن ضبط -Server لاسم المثيل الحقيقي، و-ExportPath، و-BackupDirectory للمسارات الصحيحة.
الوصف التالي لطريقة Windows Integrated Authentication. طريقة sa المصرح بها من المستخدم
موثقة في [الدليل الجديد](UPLOADED-SQL-CHECK.md)، وتستخدم DPAPI ومهمة LocalService.
المثبت في الطريقة الأصلية يسأل محليًا عن **حساب Windows مخصص موجود** مصرح له بالقراءة وتشغيل مهمة مجدولة؛
لا ينشئ مستخدمًا ولا يوسع أذونات SQL. يتطلب حق log on as batch job وفق سياسة المؤسسة.
يسأل عن مفتاح الوكيل بإدخال مخفي، أو يأخذه من -AgentTokenFile إذا كان محفوظًا بأمان.
لا تكتب المفتاح أو كلمة مرور الحساب في سطر الأوامر.

يُحفظ الكود والإعداد داخل ProgramData\TrustSoftAgent:
SYSTEM وAdministrators لهم تحكم كامل، وحساب الوكيل له قراءة الكود والإعداد،
وكتابة data فقط. مفتاح الوكيل محفوظ داخل إعداد خاص بهذه الأذونات؛ ليست هذه بديلًا عن
تشفير القرص ومخزن أسرار المؤسسة. لا تُحفظ كلمة مرور Windows في ملفات الكود أو الإعداد؛
Windows يدير اعتماد المهمة. لا يستخدم التنفيذ حساب SYSTEM ولا admin لقراءة SQL.
المهمة تُسجل بأقل مستوى RunLevel Limited. لا يُستبدل تثبيت أو مهمة موجودة تلقائيًا.
سياسات PowerShell وTLS والشهادات لا تُعطّل. الفشل الجزئي أثناء التثبيت يحتاج مراجعة الأدلة
والإعداد الموجود قبل إعادة محاولة، ولا تحذف بيانات التحقيق أو النسخ.

## شهادة 1.pfx المرفقة

أفاد المستخدم بأنها اعتماد دخول مسؤول إلى الخادم. لم تُعامل كشهادة موقع أو حساب قراءة SQL.
الفحص المحلي لم يفتحها بكلمة مرور فارغة؛ لم نستخرج مفتاحًا خاصًا ولم ننسخها إلى Git أو الحزمة.
لا تتوافر هنا خدمة RDP/WinRM/HTTPS محددة تقبلها أو عنوان مصرح قابل للوصول.
تثبيت الوكيل يستخدم حساب Windows وقناة HTTPS؛ لا يحتاج هذه الشهادة افتراضيًا.
أي استخدام لاحق لها يحتاج تحديد خدمة الدخول ومضيفها وسياسة التفويض وإدخال السر على المضيف الآمن.
لا تُرسل كلمة مرور الشهادة في المحادثة.

## إثبات النجاح المطلوب على البيئة الحقيقية

1. ظهور heartbeat حي في /control ثم sql verified_read للخادم والقاعدة الصحيحين.
2. ضغط كل زر وتسجيل id/lease/وقت ونتيجة؛ HTTP 202 وحده ليس نجاحًا.
3. إيقاف **مهمة الوكيل الخاصة بنا فقط** في نافذة اختبار، والتحقق من عودتها بالمراقب،
   دون إيقاف SQL أو التصدير أو شبكة العمل. يلزم تنفيذ آمن على المضيف نفسه.
4. تجربة حجب نقطة HTTPS الأولى للوكيل فقط في بيئة اختبار وتأكيد المسار الثاني.
5. فصل قناة الاختبار مؤقتًا وتأكيد stale/expired ثم التعافي؛ لا تعطل شبكة الإنتاج.
6. اعتماد مخطط الأعمال ومطابقة عينة مالية بشكل منفصل؛ لم يتحقق ذلك بعد.
7. لا تمثل اختبارات البروتوكول المحلية أدلة على تنفيذ Windows أو اتصال الإنتاج.
