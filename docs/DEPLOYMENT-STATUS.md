# حالة النشر الحالية — المسار المجاني

- اختار المستخدم حلًا مجانيًا حقيقيًا وأجاز تغيير الأداة.
- التطبيق الجديد مهيأ على Cloudflare Workers + D1، مع واجهة ويب وAPI وطابور أوامر وتدقيق دائم.
- إعداد Render المدفوع نُقل إلى deploy/render-paid.yaml كمرجع اختياري؛ لا يوجد Blueprint
  مدفوع افتراضي في جذر المشروع، ولا تنشئ أدوات النشر الجديدة موارد Render.
- نجحت اختبارات workerd وD1 المحلي الفعلي، بما فيها استمرار الحالة بعد إعادة تشغيل runtime.
- اختبارات Android محاكاة بمتصفح Chromium، وليست فحصًا على هاتف المستخدم نفسه.
- لا موقع Cloudflare عام منشور حتى الآن، ولا اتصال SQL إنتاج مثبت.
- العائق الخارجي الحالي: قيمة CLOUDFLARE_API_TOKEN غير مربوطة بالبيئة الجارية.
  حقل السر موجود في الإعدادات بنطاق api.cloudflare.com فقط، ولم يُستبدل أي ربط سابق.
- يلزم حفظ قيمة جديدة من حساب Cloudflare مجاني في الحقل الموجود، ثم حفظ ونشر إعدادات البيئة.
  لا تضف نسخة مكررة في متغيرات البيئة ولا ترسل قيمة المفتاح في المحادثة.
- أي ربط حديث لمفتاح يحتاج اختبار API فعليًا؛ ظهور الحقل وحده لا يثبت صلاحية النشر.
- لا أدوات تنشئ أو ترقي الاشتراكات؛ الحصص المجانية محدودة ومعلنة في FREE-HOSTING.md.

## الخطوة المنفذة بعد إتاحة الاعتماد

python -m scripts.deploy_cloudflare

الأداة تحفظ الموارد السابقة، وتعيد استخدام نشر هذه المهمة فقط،
وتتحقق من العنوان الحقيقي وHTML وجلسة الإدارة وبيانات D1 قبل إعلان نجاح الموقع.
لا تختلق اسم موقع ولا تعتبر نشر الشفرة في GitHub نشرًا لخدمة الويب.

## تصحيح تشخيص Render السابق

نجح GET /v1/services بالمفتاح المحدث وأعاد قائمة فارغة، بينما أعاد /v1/owners
صفحة Cloudflare 403. إذًا الادعاء بأن كل API محظور غير دقيق.
الصورة التي أرسلها المستخدم أثبتت شرط دفع Blueprint المجهز، ولذلك غُيّر الهدف
إلى خدمات مجانية دائمة دون محاولة تجاوز Cloudflare أو فاتورة Render.
مفتاح Render المحفوظ لم يُحذف أو يُنقل إلى نطاق آخر.
