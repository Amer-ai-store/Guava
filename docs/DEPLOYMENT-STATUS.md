# حالة النشر

- مصدر خدمة الويب: render.yaml وtrustsoft/ وweb/ في فرع codex/trustsoft-deploy.
- الخدمة المجهزة: Render Python web service، بخطة starter وقرص دائم 1 GiB.
- أوامر الاختبار المحلي نجحت بعد استعادة بيئة العمل.
- اتصال GitHub واستعلام صلاحيات المستودع نجحا؛ للمهمة صلاحية رفع المصدر.
- اعتماد Render محفوظ في البيئة بنطاق api.render.com.
- طلب قراءة owners من API أعاد HTTP 403 وصفحة حظر Cloudflare.
  الرد ليس نتيجة توثيق JSON من Render، ولا يثبت صلاحية أو عدم صلاحية المفتاح.
- لم يُنشأ موقع أو قرص أو اشتراك Render من هذه الجلسة، ولم يتحقق رابط HTTPS عام.
- أي مفتاح API أُرسل كنص في المحادثة يجب استبداله من إعدادات الحساب،
  ووضع البديل في الحقل الآمن، دون نسخه إلى Git أو التقارير.
- الأدلة المحلية التفصيلية تبقى في docs/evidence داخل مساحة العمل ولا تنشر مع المصدر.

## متابعة النشر عند زوال العائق

المسار الآلي: استخدام واجهة Render الرسمية بعد إتاحة الطلبات لهذه البيئة
وبعد ربط المفتاح البديل الآمن، ثم التحقق من الحساب والخدمة القائمة قبل إنشاء موارد جديدة.

المسار الرسمي اليدوي: من Dashboard الخاص بـRender اختر إنشاء Blueprint،
واربط المستودع Mohammadzxzx1991/Guava واختر الفرع codex/trustsoft-deploy.
راجع الخطة والقرص والتكلفة قبل اعتماد الإنشاء. لا تفترض أن نشر المصدر ينشئ استضافة تلقائيًا.
المفاتيح الثلاثة للوحة تولدها المنصة؛ لا ترسلها في المحادثة.
بعد ظهور عنوان الخدمة افتح /control بمفتاح الإدارة، ثم يلزم تثبيت وكيل Windows مرة واحدة.
نجاح /healthz يثبت عمل الويب فقط؛ لا يثبت اتصال Jawafa_DB أو تشغيل الوكيل.
