# حالة النشر الحالية

- **الموقع:** [https://trustsoft-control.zxzx-mohammad91.workers.dev/control](https://trustsoft-control.zxzx-mohammad91.workers.dev/control).
- نجح نشر Worker وربط D1 وتخزين أسرار التطبيق داخل Cloudflare.
- نجح التحقق العام من HTTPS وHTML، ودخول الإدارة، ومنع المستخدم غير المصرح له،
  وفصل القارئ عن الإدارة، وحفظ طلب فحص في D1، وفتح الواجهة بمحاكاة Android.
- تحقق مسار التحاق الوكيل بأمان دون إرسال heartbeat مزيف أو نتيجة SQL اصطناعية للإنتاج.
- طلب الفحص المنشأ أثناء التحقق ينتظر وكيل الخادم ولم يُنفّذ هناك.
- لم يُفعّل اشتراك مدفوع. أُزيل إعداد CPU المخصص، ويطبق حساب Free حدوده الافتراضية.
- ملفات مفاتيح التطبيق وتسليم الإدارة خاصة داخل local/cloudflare، خارج Git ومجلد الويب.
  لا توجد مفاتيح أو شهادة PFX في المستودع أو الحزمة العامة.
- **مرحلة الخادم المتبقية:** تثبيت Windows Agent مرة واحدة على JAWAFFASVR، بهوية قراءة
  SQL مصرح بها وشهادة SQL موثوقة، ثم التحقق من SQL الحقيقي والتصدير والنسخ.
- ظهور عنوان الموقع أو نجاح /healthz لا يثبت اتصال Jawafa_DB أو صحة بيانات مالية.

## تفاصيل الإصلاح في مرحلة النشر

رفض Cloudflare تخصيص cpu_ms لحساب Free برمز 100328، فأزيل التخصيص دون ترقية.
قُبل التعريف الصريح والصادق لعميل التطبيق في User-Agent، ونجحت الطلبات العامة.
العميل الافتراضي غير المعرّف بشكل مناسب كان يتلقى 1010؛ لم نستخدم أدوات تخفّي
أو نغيّر مسار proxy أو نعطل تحقق TLS أو نحل تحديات CAPTCHA.
مصدر خدمة الويب ووكيل Windows مرفوعان في codex/trustsoft-deploy.
الأدلة التفصيلية الخاصة موجودة في docs/evidence/public-cloudflare-api.json
وdocs/evidence/cloudflare-public-browser.json داخل مساحة العمل، خارج Git.
