# تشغيل اللوحة من Android عبر الويب

اللوحة تطبيق ويب، وليست APK أو برنامج PowerShell للهاتف.
ملف ZIP هو شفرة المشروع؛ فتح HTML من التنزيلات لا يشغّل API أو الجلسات أو قاعدة البيانات.

## الحالة الفعلية

- لا يوجد حتى الآن عنوان HTTPS منشور أو حساب استضافة مرتبط بهذه الجلسة.
- أكد المستخدم أنه يفتح ZIP/HTML من التنزيلات، وأنه لا يملك استضافة.
- لذلك لا يمكن تقديم ملف آخر على أنه رابط لوحة يعمل.
- لا يحتاج الهاتف PowerShell أو الشهادة الإدارية أو AnyDesk لفتح الموقع بعد نشره.
- وكيل Windows يحتاج التثبيت مرة واحدة في شبكة الخادم لإدارة الفحوص عن بعد.

## الإصلاح والتحقق

أزيل الاعتماد على AbortSignal.timeout، واستبدل بمهلة تستخدم AbortController عند توفره.
شُخّص فشل الدخول عند غياب هذه الدالة في متصفح Android قديم/داخل تطبيق.
حُسنت حقول الإدخال ومقاسات اللمس والتمرير وعرض أخطاء غياب الجلسة/HTTPS.
تتحدث الواجهة عند عودة الشبكة أو العودة من الخلفية.
عند فتح ملف محلي تتوقف طلبات الدخول وتظهر رسالة توضح الحاجة لرابط موقع منشور.

اختبار Chromium فعلي مع محاكاة Android نجح على المقاسات:
393x851، 360x800، 320x640، 851x393.
شمل الدخول وإرسال طلب فحص إلى مخزن اختبار محلي، دون اتصال إنتاج أو أي بيانات مالية.
نجح التعافي من انقطاع شبكة المتصفح وظهور خطأ مفيد عند غياب ملف ارتباط الجلسة.
لا يوجد تجاوز أفقي للصفحة، وأزرار التشغيل بارتفاع 44px على الأقل.
هذه محاكاة Android وليست تجربة على جهاز المستخدم نفسه.
اختبار file:// منعه نهج المتصفح في بيئة الاختبار؛ لم نغير النهج.
جرى اختبار حارس الملفات المحلية بمختبر DOM في Node بشكل مستقل.

الأدلة: evidence/android-baseline.json وevidence/android-browser-results.json
والصورة evidence/android-control.png.
التشغيل التطويري: python -m scripts.mobile_browser_check
يتطلب Playwright وChromium، ولا يضيفهما إلى متطلبات تطبيق الإنتاج.

## النشر

جُهز render.yaml في جذر المشروع لخدمة Python خلف HTTPS مُدار وقرص دائم لقاعدة التحكم.
هذا إعداد قابل للمراجعة وليس نشرًا منفذًا.
الخطة starter والقرص الدائم موارد مدفوعة؛ لا تنشأ موارد أو تكاليف من كتابة الملف.
يلزم حساب استضافة يفتحه المستخدم، وربط المستودع/أداة النشر.
مصدر النشر هو الفرع codex/trustsoft-deploy؛ راجع DEPLOYMENT-STATUS.md لحالة الرفع والاستضافة.
لا تُرسل مفاتيح حساب الاستضافة في المحادثة.

بعد النشر يُفتح عنوان الخدمة الفعلي مع المسار /control في Chrome.
يُستخدم مفتاح إدارة الموقع، ولا يُحمّل ZIP على الهاتف.
المضيف المُدار يتولى HTTPS؛ تشغيل Python على 0.0.0.0 في هذا القالب مخصص لشبكة
الخدمة الداخلية خلف proxy المنصة، وليس لفتح منفذ Python خام للعامة.
مسار /healthz يدل على بقاء عملية الويب فقط، حتى لا يسبب عطل SQL إعادة تشغيل الموقع.
مسار /api/health محمي للمستخدم، وما يزال يعبر عن جاهزية البيانات وليس مجرد حياة العملية.

النشر واختبار الدخول بالموقع لا يثبتان نجاح SQL أو وجود وكيل Windows؛
يبقيان اختبارات مستقلة موثقة في REMOTE-CONTROL.md.
