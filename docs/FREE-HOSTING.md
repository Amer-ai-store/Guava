# النسخة الحقيقية المجانية — Cloudflare Workers + D1

هذا مسار تنفيذ حقيقي للواجهة والـAPI والأوامر المصرح بها، وليس وضع بيانات تجريبية.
نُقل broker إلى Workers، وحُفظت الطلبات والتدقيق وهوية الوكيل في قاعدة D1 دائمة.
الواجهة نفسها تعمل على Android والمتصفحات دون ZIP أو PowerShell في الهاتف.
لا يعتمد هذا المسار على قرص Render أو خادم مدفوع أو جلسة AnyDesk دائمة.

**الحالة:** اجتازت المكونات اختبارات محلية فعلية على workerd وD1 المحلي.
لا يوجد حتى الآن موقع Cloudflare منشور أو اتصال SQL إنتاج مثبت؛ اعتماد Cloudflare
غير مرتبط بالنسخة الجارية من البيئة عند آخر فحص.

## لماذا يحل عائق Render المجاني

- البيانات لا تعتمد على نظام ملفات مؤقت في حاوية مجانية.
- broker_id ثابت في D1، فلا ينكسر اقتران الوكيل بعد إعادة تشغيل Worker.
- الجلسات موقعة بمفتاح خاص ثابت، فتظل صالحة حتى انتهاء مدتها بعد تبديل نسخة Worker.
- الأوامر تحفظ بمهلة وlease فريد؛ فحوص Windows ثابتة للقراءة ولا تُعاد كتابة بيانات TrustSoft.
- لا يوجد إعداد لإلغاء التحقق من TLS أو التحايل على Cloudflare أو على فوترة Render.
- Cloudflare يصدر HTTPS لعنوان workers.dev؛ لا يلزم شراء نطاق للبدء.
- لا تُفعّل أداة النشر خطة مدفوعة أو اشتراكًا؛ يلزم استخدام حساب على Workers Free.

## الحساب والاعتماد مرة واحدة

1. أنشئ حسابًا مجانيًا أو استخدم حسابك في https://dash.cloudflare.com/sign-up .
2. من https://dash.cloudflare.com/profile/api-tokens أنشئ Custom API Token
   للحساب المقصود، بصلاحيات:
   - Account / Workers Scripts / Edit
   - Account / D1 / Edit
   - Account / Account Settings / Read
3. في إعدادات بيئة Codex افتح **الأسرار** وعدّل قيمة الحقل الموجود
   CLOUDFLARE_API_TOKEN، بنطاق api.cloudflare.com فقط.
   لا تنشئ نسخة أخرى بالاسم نفسه في متغيرات البيئة.
   مفتاح Render لا يصلح لهذا الحقل. لا ترسل قيمة المفتاح في المحادثة.
4. احفظ إعدادات البيئة وانشرها لتطبيق الاعتماد.
   هذا يفعّل صلاحية النشر؛ لا يعني أن موقع الويب نُشر تلقائيًا.

لم نستبدل أي ربط سر سابق، بما فيه RENDER_API_TOKEN ومتغيرات إصدار الأدوات.
عند توافر الاعتماد، أداة النشر تختار حسابًا واحدًا مصرحًا فقط؛ إذا وجدت عدة حسابات
تحتاج تحديد CLOUDFLARE_ACCOUNT_ID غير السري دون تخمين الحساب.

## التنفيذ للنشر

من جذر المشروع بعد تثبيت Node 22+ وPython 3.12+:

    cd deploy/cloudflare
    npm ci
    cd ../..
    python -m scripts.deploy_cloudflare

Wrangler مثبت بإصدار محدد وقفل npm مع تحقق integrity، ويستخدم proxy وشهادات البيئة.
الأداة:
- تفحص الحساب والموارد القائمة، وتحافظ على Worker أو قاعدة لا يثبت ملكيتها لهذه المهمة.
- تنشئ D1 واحدة باسم trustsoft-control، وتطبق migrations غير هادمة.
- تنشر الواجهة وWorker كخدمة واحدة، وتضبط أسرار التطبيق منفصلة عن اعتماد حساب Cloudflare.
- لا تحفظ مفتاح حساب Cloudflare في المشروع أو سجلات التطبيق أو الخدمة المنشورة.
- تبقي بيانات إعداد النشر والمفاتيح الأولية للتطبيق في local/cloudflare بأذونات خاصة،
  خارج Git والحزم؛ لا تطبع قيمها.
- لا تستبدل مفاتيح موجودة في Worker عند تكرار النشر.
- تأخذ عنوان الموقع من خرج النشر الحقيقي، وتختبر HTTPS وHTML والدخول
  وقراءة حالة D1 قبل إعلان نجاح النشر.
- لا تعتبر تشغيل الموقع إثبات اتصال SQL؛ يحتاج الوكيل تثبيتًا واحدًا على JAWAFFASVR.

الصلاحيات والخطة ليست محددة كخطة Render starter؛ لا تحتاج إدخال بطاقة في تصميم هذا المسار.
إذا طلب الحساب تفعيل خطة مدفوعة، توقف ولا تعتمد ذلك؛ ليس جزءًا من هذا النشر.

## حدود المجاني الموثقة

بحسب الوثائق الرسمية التي فُحصت أثناء التنفيذ:
- Workers Free: 100,000 طلب ديناميكي يوميًا و10ms CPU لكل استدعاء.
- D1 Free: 5 ملايين صف مقروء يوميًا و100,000 صف مكتوب يوميًا.
- إجمالي تخزين D1 المجاني: 5GB للحساب، وحد القاعدة الواحدة 500MB.
- عند تجاوز حدود المجاني تتوقف العمليات المعنية بأخطاء quota؛ لا تُرفع الخطة تلقائيًا بواسطة الكود.
- لا ضمان خدمة SLA مدفوعًا أو سعة بلا حدود في الخطة المجانية.

المصادر الرسمية:
https://developers.cloudflare.com/workers/platform/pricing/
https://developers.cloudflare.com/d1/platform/pricing/
https://developers.cloudflare.com/d1/platform/limits/

تستخدم خدمة التحكم فهارس للصفحات وآخر الأوامر لتجنب مسح التاريخ كله في كل تحديث.
يفحص الوكيل القناة كل نحو 20 ثانية مع jitter، وفحص SQL التلقائي يتحقق من
الهوية والصلاحيات دون إعادة نقل المخطط الكامل كل دقيقة.
إذا تجاوز تقرير المخطط 192KiB يبقى التقرير الكامل في history المحلي المحمي،
وتُرسل عينة 100 عمود و100 علاقة مع العدد الإجمالي ووصف sample.
لا توصف العينة بأنها مخطط كامل، ولا تُخمن روابط الأعمال أو البيانات المالية.
الرفع محدود إلى 512KiB في طلب النتائج. لا تُرفع صادرات CSV ذات 822MB إلى D1.
النسخ والملفات الأصلية تبقى على خادمها؛ اللوحة تجرد بيانات وصفية فقط.
لا ينفذ الكود تنظيفًا تلقائيًا لأدلة التحقيق أو ترقية مدفوعة عند امتلاء الحصة.

## ما اختُبر فعلًا

    python -m scripts.check_free_worker

يشغل Wrangler/workerd الرسمي وD1 محليًا بأسرار اختبار فقط، دون اعتماد حساب سحابي.
نجحت اختبارات:
- تقديم موقع الويب وحماية API.
- فصل القارئ والإدارة والوكيل ورفض CSRF والأوامر غير المسموحة.
- استمرار الطابور وهوية broker والجلسة الموقعة بعد إيقاف runtime وإعادة تشغيله.
- lease واحد فقط عند طلبين متزامنين.
- رفض lease مزور ونتيجة معاد إرسالها.
- حماية الحالة من قاعدة SQL باسم مختلف، وعدم عرض عينة المخطط كمخطط كامل.
- فحص SQL تلقائي خفيف وحد أقصى لحجم الرفع.
- بقاء فهرس النسخ القادم من الوكيل دون وصفه بأنه نسخة قابلة للاستعادة.
- إبطال جلسات الإدارة القديمة عند تغيير مفتاحها مع الحفاظ على جلسات القارئ.
- دخول متصفح Chromium بمحاكاة Android إلى Worker وD1 الفعليين محليًا.

بيانات SQL في الاختبارات اصطناعية داخل المختبر، وليست بيانات مستخدم حقيقية.
لم يُشغل Windows Agent أو SQL إنتاج من هذه الجلسة.
لم يُختبر CPU على Cloudflare العام حتى الآن؛ حدود الخطة فعلية وقد تمنع عملية ثقيلة.
تهيئة الجداول والعلاقات والدفاتر والتقارير المالية من مخطط TrustSoft الحقيقي ما تزال تحتاج
وصولًا مصرحًا للمصدر ومطابقة عينات، ولا يمثل نجاح الاستضافة إثباتها.

## ما بعد ظهور الرابط الحقيقي

يفتح المستخدم رابط الموقع في Chrome من الهاتف، ويسجل بمفتاح الإدارة الخاص.
يثبت مسؤول الخادم وكيل Windows مرة واحدة بالعنوان الجديد ومفتاح الوكيل المخصص.
من ثم تُقرأ فحوص الاتصال وSQL والتصدير والنسخ من اللوحة، وتعمل إعادة المحاولة
المعتمدة دون فتح AnyDesk في كل مرة.
الجهاز المطفأ أو انقطاع الإنترنت المادي الكامل يحتاج عودة الطاقة/الشبكة أو قناة عتادية مستقلة؛
اللوحة لا تدعي تشغيل جهاز غير متاح.
