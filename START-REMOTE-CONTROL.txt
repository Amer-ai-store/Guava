TrustSoft — لوحة الاتصال والتعافي + وكيل Windows

هذه حزمة المشروع ولوحة الإدارة المستقلة، وليست موقعًا منشورًا أو إثبات اتصال ناجح.
ابدأ بقراءة docs/REMOTE-CONTROL.md.

الهدف بعد الإعداد مرة واحدة:
تفتح لوحة /control من الهاتف أو أي جهاز، وتفحص الاتصال بالخادم وقاعدة البيانات
والتصدير والنسخ دون فتح AnyDesk كل مرة، مع retries ومراقب تشغيل للوكيل.

المطلوب مرة واحدة:
1. نشر مجلد المشروع على مضيف Linux دائم، مع Python 3.12+ وعنوان HTTPS حقيقي.
   قوالب الخدمة وreverse proxy داخل deploy تحتاج إعداد المضيف والشهادة وDNS الفعليين.
2. توليد/إعادة استخدام مفاتيح مستقلة دون إظهارها:
   python3 -m scripts.prepare_control --directory /etc/trustsoft
   لا تعِد إنشاء ملف مفاتيح موجود، ولا ترسل القيم في المحادثة.
3. ضبط متغيرات خدمة اللوحة كما في الدليل، خاصة TRUSTSOFT_SOURCE=agent
   وTRUSTSOFT_CONTROL_DB ومسار النسخ الاختياري.
4. على JAWAFFASVR، افتح Windows PowerShell كمسؤول للتثبيت فقط وشغّل:
   .\agent\Install-TrustSoftAgent.ps1 -DashboardUrl 'https://YOUR-REAL-DASHBOARD-HOST'
   استبدل العنوان بموقعك الفعلي؛ العنوان المثال غير منشور.
   سيطلب حساب Windows مخصصًا للقراءة وتشغيل مهمة مجدولة، ومفتاح الوكيل بإدخال مخفي.
   لا تستخدم حساب مسؤول لقراءة قاعدة الإنتاج.
5. افتح /control على موقعك وادخل بمفتاح الإدارة الخاص، ثم افحص heartbeat ونتائج الأزرار.

الشهادة 1.pfx ليست داخل الحزمة. وُصفت بأنها اعتماد دخول مسؤول، ولم تستخدم كشهادة الموقع.
لا تحتاج الحزمة لاستخراج مفتاحها الخاص أو نشره.
المثبت ينشئ مهمته الخاصة فقط ولا يغيّر مهام التصدير أو SQL أو بيانات TrustSoft.
لا يُطلق تصديرًا آخر أو يوقف العملية 9276. لا تعطل TLS أو سياسات PowerShell.
الطلب Accepted أو queued ليس اتصال SQL ناجحًا؛ راجع النتيجة والهوية والتوقيت.
الفحوص المحلية لا تثبت نجاح التنفيذ على Windows؛ اختبر الخطوات المذكورة بالدليل على المضيف.
