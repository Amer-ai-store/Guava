# TrustSoft Central Dashboard

## النشر المجاني الحقيقي

المسار الحالي هو Cloudflare Workers + D1: واجهة ويب وAPI وتخزين دائم للطلبات،
دون قرص Render مدفوع. [الإعداد والحدود والأدلة](docs/FREE-HOSTING.md).
يلزم حساب Cloudflare مجاني وربط الحقل الآمن الموجود CLOUDFLARE_API_TOKEN.
لم يُنشر موقع عام أو يُختبر اتصال SQL إنتاج حتى الآن.

إعداد Render في deploy/render-paid.yaml بديل مدفوع محفوظ فقط؛ لا تستخدمه إذا أردت المسار المجاني.

واجهة عربية RTL وخدمة قراءة محلية داخل مستودع Guava القائم.
**لم يتحقق اتصال Jawafa_DB بعد، ولا توجد بيانات إنتاج أو نشر أونلاين مثبت.**
راجع [تقرير التنفيذ](docs/VERIFICATION.md).

## التشغيل

Python 3.12+؛ الخدمة والواجهة والاختبارات الأساسية بلا حزم خارجية.
من جذر المشروع، جهّز TRUSTSOFT_API_TOKEN بمفتاح عشوائي قوي لا يقل عن 32 محرفًا
عبر مخزن أسرار الخدمة، ثم شغّل:

    python -m trustsoft.server --host 127.0.0.1 --port 8080

لا تحفظ المفتاح في Git أو المحادثة. ملف تعريف الارتباط Secure افتراضيًا.
لاستخدام HTTP على loopback فقط اضبط TRUSTSOFT_SECURE_COOKIE=0.
في الإنتاج أبقه 1 مع reverse proxy وTLS موثوق وحدود طلبات واتصالات.

هذا خادم تطوير وليس نشرًا عامًا مقسى. قبل إتاحة بيانات مالية أونلاين يلزم:
SSO/MFA، حسابات وصلاحيات منفصلة لكل قسم، سجل وصول محمي، دوران أسرار، وTLS.
المفتاح الحالي يمنح كل الأقسام لحامله؛ لا توزعه على مستخدمين مختلفي الصلاحيات.

## ربط SQL

المسار الموصى به عند غياب VPN هو تشغيل الخدمة على JAWAFFASVR أو مضيف داخلي مصرح،
بهوية Windows مخصصة للقراءة، ثم إتاحة الواجهة عبر HTTPS مُدار. لا تفتح SQL للعامة.
لم ننشئ مستخدمًا أو نغير صلاحيات قاعدة البيانات.

يتطلب الموصل الاختياري Microsoft ODBC Driver 18 و:

    python -m pip install -r requirements-sql.txt

لم يُثبت الموصل في هذه الجلسة ولم يُختبر مع خادم حقيقي.
اضبط TRUSTSOFT_SQL_CONNECTION في بيئة الخدمة المحمية، مع قاعدة Jawafa_DB،
وEncrypt=yes;TrustServerCertificate=no وشهادة موثوقة باسم المضيف.
يمكن استخدام Windows Integrated Authentication على مضيف مدعوم.
هذه قيمة اتصال مباشرة وليست سر HTTP يحقنه proxy. لا ترسل كلمة المرور في chat.

    python -m scripts.probe_sql

يفحص الهوية والكتالوج والعلاقات. ترفض الخدمة صلاحيات الكتابة والتنفيذ المكتشفة؛
هذا دفاع إضافي لا يغني عن تدقيق DBA للأذونات والأدوار والصلاحيات الموروثة والخادم.
لا توجد واجهة SQL عامة أو تصدير تلقائي. دورة قراءة واحدة متسلسلة:
مهلة اتصال 5 ثوانٍ، استعلام 8 ثوانٍ، انتظار قفل ثانيتين، وحد 200 صف لكل قسم،
مع rollback وإغلاق الاتصال. حد الميتاداتا 20,000 صف لكل استعلام؛ تجاوزه يوقف الدورة.
التحديث كل 30 ثانية بعد انتهاء الدورة، والتراجع بعد الفشل يصل إلى 240 ثانية.
طلبات المستخدمين تقرأ cache ولا تستعلم مباشرة. لا تُكشف أخطاء المشغل التفصيلية.

## اعتماد أقسام الأعمال

لا نستنتج معنى الجداول من أسمائها. تحقق بعينات مع المشغل المالي من المفاتيح والعملات
والفترات والإلغاءات ثم انسخ docs/mapping.example.json إلى مسار محلي محمي خارج Git،
واضبط TRUSTSOFT_MAPPING. المثال أسماء بديلة وليس مخططًا مكتشفًا.
اعتمد عروض قراءة محدودة ومفهرسة؛ لا توجه الربط إلى جداول ضخمة قبل مراجعة خطة الاستعلام.
الأقسام:
sales, purchases, accounting, checks, inventory, users, operations, financial, vouchers, payments, audit.
الترتيب تصاعدي بحسب order_by؛ نطاق الفترة يحدد في عرض المصدر المعتمد.
أسماء الأعمدة والكائنات تُطابق بالكتالوج وتُقتبس؛ لا تمرر SQL في الربط.
لا تعرض كلمات مرور أو رموز دخول أو بيانات شخصية غير لازمة.
العينات ليست إجماليات مالية.

التحقيق يدعم مرشحات دفعات مكررة بالأعمدة المنطقية:
payment_id, party_id, amount, currency, reference, date.
يلزم تطبيع المنطقة الزمنية وتحديد الكيان التجاري في عرض المصدر.
التعديلات وفك الترحيل تحتاج سجلًا موثوقًا:
event_id, document_id, event_type (edit/unpost), user, device, timestamp, before, after.
لا تُخمن هوية المستخدم أو الجهاز. السندات المفقودة غير محللة:
يلزم تسلسل كامل لكل شركة وفرع وسنة ونوع مع الإلغاءات ومطابقة الدفاتر.
المرشحات ليست إثبات حذف أو اختلاس، والعينة لا تثبت غياب سند.

## فحص الجسر والتصدير

على JAWAFFASVR:

    powershell -NoProfile -File scripts/inspect-server.ps1

فحص قراءة فقط للخدمات ومستمع 3456 وعمليات v2/v3 وحالة المهمة وملخص التصدير والسجل.
لم يُنفذ على Windows هنا. لا يغير الجدولة أو يوقف PID 9276.
لا نفترض عقد API للجسر المجهول.

على تصدير مستقر غير نشط فقط:

    python -m scripts.audit_export <directory>

أعد توجيه الناتج إلى تقرير مستقل جديد خارج مجلد المصدر. يفحص CSV واحدًا تلو الآخر:
صفوف منطقية وأعمدة وSHA-256 وتغير الملف أثناء القراءة.
يدعم --manifest بملف JSON: قائمة كائنات file/rows/sha256 من مصدر موثوق.
تطابق الملفات لا يثبت اتساق لقطة SQL. لا يحذف نسخًا أو سجلات أو يبدأ تصديرًا.
525 ملفًا مقابل 1,024 جدولًا لا يثبت اكتمالًا أو يحدد المفقود.

لا تعدل المهمة من v2 إلى v3 قبل مراجعة السكربتين ومعرفة حالة العملية النشطة وسبب الفشل.
لا تشغل تصديرين متوازيين ولا تحذف أدلة.

## التحقق

    python -m unittest discover -s tests -v
    python -m scripts.smoke_live
    node --check web/app.js
    python -m scripts.probe_sql

الأخير يفشل صراحة حتى تهيئة الوصول. المصادر الاصطناعية داخل tests فقط.
اختبار smoke يشغل عملية الخدمة الفعلية، ويفحص الدخول وHTTP وحالة SQL غير المهيأ،
ثم يوقف عمليته فقط.

للفحص المباشر على Windows دون Python أو جسر 3456، راجع
[دليل فحص SQL بهوية Windows](docs/WINDOWS-CONNECTION.md) و
[حزمة الفحص](docs/deliverables/windows-sql-probe.zip).
هذا المسار مُعد ولم يُنفذ على الخادم بعد.

الحزمة الأسهل للتنفيذ على السيرفر:
[تحميل TrustSoft-Server-Check.zip](docs/deliverables/TrustSoft-Server-Check.zip).
فكها في C:\TrustSoftCheck وشغّل Run-TrustSoftCheck.cmd، ثم أرسل ZIP الناتج داخل reports.
راجع START-HERE.txt قبل التشغيل؛ لا تحتاج Python ولا كلمة مرور في المحادثة.

## لوحة اتصال مستقلة ووصول من المنزل

أضيف المسار /control بمفتاح إدارة مستقل، وأوامر قراءة محددة عبر وكيل Windows صادر.
تشمل retries، طابورًا دائمًا، مراقب تشغيل، مسار HTTPS احتياطيًا اختياريًا،
وجرد التصدير والنسخ. لا تحتاج فتح AnyDesk بعد تثبيت الوكيل وإثبات عمله مرة واحدة.
راجع [دليل الاتصال والتعافي](docs/REMOTE-CONTROL.md) و[النتائج الحالية](docs/VERIFICATION.md).
الموقع غير منشور والوكيل لم يُثبت على الخادم؛ لا يكفي ملف PFX إداري لإنشاء قناة وصول.
اختبارات المشروع مجتمعة: python -m scripts.verify.

## Android ومتصفح الهاتف

لا تُفتح اللوحة من ZIP/HTML في التنزيلات؛ تحتاج رابط موقع منشور.
أُصلحت مهل الطلبات لتعمل دون AbortSignal.timeout، وحُسنت شاشات الهاتف.
راجع [طريقة الويب والنشر ونتائج اختبار Android](docs/ANDROID-WEB.md).
ملف deploy/render-paid.yaml إعداد نشر فقط، وليس رابط موقع أو إنشاء استضافة.
